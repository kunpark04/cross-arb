## Methodological Audit

- **Choice of model:** A two-pool deterministic capital walk with per-leg cost split is the right instrument for the question ("does the $250/$250 split bind differently than one $500 pool"). Reusing the frozen `run_funnel` gate stack + the now-live velocity gates is the correct, non-duplicative approach ([L20] discipline respected — no economics re-implemented). The economics formula `profit = size·max(0, book_avg_edge − void)` with `book_avg = max(0.005, (open_net+0.005)/2)` is **identical** to `capital_sim.simulate` / `cap_constrained_entries` (recomputed top-3 positions, match to 1e-9). Good.

- **Assumptions that hold:** profit counted once per market (`one_per_market`; 0 duplicated markets in cohort); restart-censored phantoms dropped (`drop_restart=True`); fat-edge haircut applied (20c/13c ITF sized ×0.5); settlement frees both pools; `settle_t` uses only slug-date + open (no future leakage).

- **Assumption that FAILS — `leg_split` direction labels (CRITICAL #1).** `venue_split_backtest.py:59-70`. The binary branch is `if d=="PK": p=p_ya,k=1-k_yb  else: k=k_ya,p=1-p_yb`. But binary (weather/econ) dirs in the data are the **single letters `"P"`/`"K"`** (confirmed: weather dir mix {K:1593, P:1175}; sports {PK, KP}). The authoritative cheap/dear mapping is `adverse_selection._legs`: dir `P` ⇒ buy YES@pmus (cost `p_ya`) + buy NO@Kalshi (cost `1-k_yb`); dir `K` ⇒ buy YES@Kalshi (cost `k_ya`) + buy NO@pmus (cost `1-p_yb`). Because `"P" != "PK"`, **every dir-`P` episode falls into the else/`KP` formula** → it computes the Kalshi share using `k_ya` and `1-p_yb` (the dir-`K` legs). dir-`K` is coincidentally correct (else-branch == K formula); dir-`P` is wrong. Measured on the live cohort: 4 of 6 dir-`P` weather episodes mis-split, e.g. `tc-temp-laxhigh-2026-06-11-gte78lt79f` (the #1 weather profit position, $3.19) gets kfrac **0.085 vs correct 0.948** — nearly inverted. The selftest (`:204-218`) passed only because it fed synthetic `"PK"`/`"KP"` to the binary cases, masking the bug. **Impact:** because both pools are $250 and the walk barely binds, the headline moves only trivially (weather 15→16 entered, $13.006→$13.035 = +2.60%→+2.61%; all-verified unchanged; at a tight 50/50 bankroll PnL is identical). So the bug is **immaterial to the magnitude but defeats the per-venue purpose**: the "peak deployed Kalshi 99% / pmus 100%" line and any "which venue binds first" claim are computed on a wrong split for the cheap-pmus legs. Fix: branch on `d in ("P","PK")` vs `("K","KP")` with the binary/sports shape selected by px keys, not by the `PK`/`KP` literal. Verify by re-running `--selftest` with the *real* labels `"P"`/`"K"` (the test must assert the dir-`P` kfrac equals `(1-k_yb)/((1-k_yb)+p_ya)`).

- **Alternatives not considered:** none needed for the model itself, but the script should have (a) asserted the dir labels it receives, (b) printed per-position profit so the concentration was visible without a reviewer reconstructing it, (c) defaulted `drop_flat=True` or at least reported the flat-ladder profit share (see Data Audit).
